# COBOL Application Test Plan

このテスト計画は、現在の COBOL アプリケーションにおけるビジネスロジックと実装の検証に使用するためのものです。後続の Node.js への移行に備え、各テストケースについてステークホルダーが確認できるように構成しています。

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TC-01 | 初期残高の表示 | アプリケーション起動後、まだ操作をしていない状態 | 1. アプリを起動する
2. メニューで「1」を入力する | 初期残高 `1000.00` が表示される |  |  |  |
| TC-02 | 入金処理の実行 | アプリが起動している | 1. メニューで「2」を入力する

| TC-03 | 出金処理の実行（残高あり） | 残高 `1000.00` 以上の状態 | 1. メニューで「3」を入力する

| TC-06 | メニューで範囲外の番号を入力 | アプリが起動している | 1. メニューで `5` または `0` などを入力する | 「Invalid choice, please select 1-4.」が表示され、再度メニューが表示される |  |  |  |

| TC-09 | 複数操作後の残高整合性 | 入金と出金を連続実行した後 | 1. メニューで「2」を選択し `300` を入金
2. 次に「3」を選択し `100` を出金
3. 最後に「1」を選択して残高を表示 | 最終残高は `1200.00` になる |  |  |  |

## カバレッジ

本テスト計画は以下のビジネスロジックを網羅しています。

- メニュー操作の正しい選択と無効入力の検証
- 残高照会（CURRENT BALANCE）
- 入金処理（CREDIT）
- 出金処理（DEBIT）
- 残高不足時の拒否処理
- アプリケーション終了処理
- 異常入力（非数値・範囲外選択）の動作確認

## 今後の Node.js 移行時の補足

Node.js 版では、以下の点をユニットテストおよび結合テストで明確に扱うべきです。

- 入力検証の強化（数値以外の入力を明示的に拒否）
- メニュー選択の厳格な判定
- 残高更新ロジックの単体テスト（加算・減算・不足判定）
- データ永続化／状態管理の検証
- 例外発生時の表示メッセージと再試行フロー
